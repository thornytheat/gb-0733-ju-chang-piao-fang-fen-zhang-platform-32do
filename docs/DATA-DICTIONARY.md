# 票房数据字典

## 输入契约

一次发布提交以规定文件名标识的五份 CSV，可再附一份可选的 `fees.csv` 服务费结算单。列顺序可变，列名匹配区分大小写。先解码 UTF-8（允许 BOM），失败改用 GB18030。CSV 原值保留字段数组及物理起止行。重复表头和空行单独计数。缺列、截断引号、无法解码、中途超限时整批失败。单条多列或少列按 `COLUMN_COUNT` 隔离。

| 文件 | 字段及定义 |
|---|---|
| `tickets.csv` | `ticket` 字符串票码，`paid_at` 收款时刻，`amount` 金额，`unit` 元或分，`status` 仅 `paid` 可入账，`note` 可空说明 |
| `shows.csv` | `show` 场次键，`title` 演出名，`venue` 场馆，`publication_status` 为 `open` 或 `held`，`opens` 和 `closes` 为核销起止，`cancelled_at` 空串表示正常场次 |
| `rights.csv` | `ticket`、`show` 唯一组合，`weight` 为 1 至 10,000 的整数 |
| `scans.csv` | `scan_id` 核销流水号，`ticket`、`show`、`scanned_at` 入场时刻，`gate` 为闸口名 |
| `refunds.csv` | `refund_id` 退款流水号，`ticket`、`show`、`refunded_at` 退款时刻，`amount`、`unit` 为实际退款请求 |
| `fees.csv`（可选） | `statement_id` 渠道结算单号，`ticket`、`billed_at` 出账时刻，`amount`、`unit` 为整张套票的服务费金额 |

编号允许英文、数字、连字符和下划线，最多 64 字符，首位须为英文或数字，前导零保留。字符串前后空格去除。必填字段中的空串、`-`、`N/A`、`NULL`、`未知` 进入隔离。表头为空、文件只有空行有不同错误，表头存在且无数据可用于零权益、零核销或零退款。有效票源和场次均至少一条。

时间输入须是带 `Z` 或数值偏移的 ISO 秒级时间，归一为 UTC，首页显示上海时间。核销时间窗 `[opens, closes)`。核销不得早于收款，停演时刻起不再核销。重复核销先按标准时刻排序，同刻按流水号升序；最早有效票场事件保留。相同业务键的完全相同记录保留最早来源，冲突组全数隔离。票源 `note` 不参与同一业务记录判断。

金额可用全角数字、规范千位分组。元最多两位小数，分只收整数文本。单笔金额须为正，最多 9,999,999,999 分。解析时用 Decimal 转分，其余金额运算使用整数。每份文件的上限保证批次汇总落在 JavaScript 安全整数范围内。

## 发布及冲正

首次发布只把实收分给 `open` 且有有效权益的场次。每份先取整，剩余分按余数降序、场次键升序分配。`remainder` 是分子整除权重和后的整数余数，`rank` 是分发顺序，`extra_cents` 只能为 0 或 1。无合资格权益的票款进入未结余额，保留 `NO_ELIGIBLE_RIGHTS`。

`publication_status` 表示原发布资格。`cancelled_at` 卡住后续核销，并让该场剩余原分账不进入场馆应收。停演场次退款至少在停演和收款之后，时刻相等也合法。退款按时刻和流水号升序逐条试扣，单笔越过剩余限额时整笔隔离、额度保持不动。冲正为负分，显示余额和退款统计为非负分。补报须保留已通过的退款编号、金额和业务事实，无法保留的修订返回 `REFUND_CHANGED`。

原发布保存票源、场次定义、权益的摘要及其来源行。变化后的原始定义需要使用不同账册编号。核销、退款与可选服务费可追加或修订，返现操作由外部渠道完成。账册保留每次发布的输入快照，不提供跨账册合并。

## 服务费归属

渠道按整张套票出一张结算单，单笔 `fees.csv` 行的金额是整单票面，不可拆分改写。归属只按该票的原分账场次份额展开：用与原分账相同的最大余数法把整单金额按权重分成场次份额，各份额之和恒等于整单金额（`fee-lines` 校验）。

每一份场次份额再判定是否落到场馆：

- 该票在该场次有有效核销且场次未停演 → 落到该场次所属场馆，计入「场馆承担服务费」。
- 场次已停演 → 不落任何场馆，原因 `FEE_CANCELLED_SHOW`。
- 该票在该场次无有效核销 → 不落任何场馆，原因 `FEE_AWAITING_SCAN`。
- 该票没有可分摊的原分账 → 整笔不落场馆，原因 `FEE_NO_RIGHTS`。

未落地份额不进任何场馆的成本，单独列在「未落地」并按原因汇总，说明去向。场馆净应收 = 场馆应收 − 落到该场馆的服务费。同一结算单重跑按运行编号幂等复用，不重复扣减；修订若遗漏或改写已入账服务费返回 `FEE_CHANGED`，旧批次净额与明细仍可按运行编号查回。

## 勾稽与凭证

- `净收款 = 实收票款 − 已入账退款 = 场馆应收 + 未结余额`。逐票检查，避免两票串账互相抵消。
- `原分账 = 场馆应收 + 场次未结 + 已入账退款`。差额槽的「账面差额」是原分账减应收，勾稽差异是扣除场次未结和冲正后的剩余值。
- `整单服务费 = 落地服务费 + 未落地服务费`。落地按场馆汇总，未落地按原因汇总，两者守恒。
- 场馆应收只计正常场次的有效核销。未结包括未核销、停演未退完及未分配票款。
- 源行守恒按逻辑记录计，`逻辑行 = 采信 + 隔离 + 空行 + 表头`。相互冲突的每条原始记录只计一次。
- ZIP 同时保留本次输入、原分账来源和结果 CSV，含 `fee-lines.csv`、`fee-shares.csv`、`fee-unlanded.csv`、`fee-statements.csv`、`fee-venues.csv` 与 `venue-net-receivable.csv`。`manifest.json` 含入参、版本、运行编号、原发布编号、时间、耗时、逐文件 SHA-256、勾稽检查、服务费汇总及汇总。JSON 和原始文件逐字保留票码，CSV 复核时请将票码列按文本导入。
